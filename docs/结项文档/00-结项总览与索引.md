## 2. 项目概况

`proj_janitor` 面向长期积累大量本地代码目录的开发者，提供五个核心能力：

1. `scan`：发现项目目录，统计体积、最后修改时间、项目标记、Git 分支与工作区状态。
2. `backup`：对可恢复项目采用“Git 远程 URL + 提交 SHA”的轻量记录；对不可恢复项目回退为 `tar.gz` 归档，并写入清单与 SHA-256。
3. `restore`：按 manifest 恢复 Git 项目或归档项目，默认恢复到 manifest 记录的原始位置，也可用 `--dest` 恢复到新目录；默认校验归档 SHA-256，不覆盖已有目标目录。
4. `verify`：只读校验归档 SHA-256；Git 记录只验证 metadata，不检查远程可用性。
5. `clean`：按白名单规则识别构建产物与依赖缓存，默认只展示计划，显式确认后才删除。

项目提供 Rust CLI（推荐用 `cargo install` 安装）和 Python 版（Python 源码元数据版本仍为 `0.1.0`，未发布至 PyPI）；通过 `projjan` 或 `python3 -m proj_janitor` 运行。无服务端、数据库、Web UI 或网络监听；Git 恢复/可恢复性检查按需访问远程 Git。

## 3. 结项范围与结论

### 3.1 已完成范围

- 项目扫描与项目标记识别。
- GitHub 远程 URL 校验与 URL-only 可恢复性判定；支持内嵌 PAT 的 HTTPS URL，并在清单和输出中脱敏。
- 安全备份策略：Git 记录、`tar.gz` 归档、manifest v2、逐项目备份目录。
- 按 manifest 恢复 Git 项目或归档项目，支持原始位置和 `--dest` 两种目标，包含 SHA-256 校验、安全解压、`source` 路径校验和拒绝覆盖。
- 构建产物清理计划、规则筛选、显式确认删除与符号链接防护。
- CLI 文本/JSON 输出、退出码、帮助与规则列表。
- 历史 Python 0.1.0 基线的 98 项测试记录保留在 06；当前 Python/Rust 测试及多平台 CI 状态见第 8 节。
- Python wheel 与 Rust crate 安装/发布验证；Rust 发布记录见 `docs/发布记录/`。
- MIT 许可证、公开 GitHub 仓库与 crates.io Rust 版本。
- README 使用说明与开发博客记录。

### 3.2 未纳入范围

- 数据库、Web 服务、图形界面、移动端。
- 生产环境部署、集群、监控告警、数据迁移。
- 运行时将用户项目备份推送到远程/云存储、增量备份与保留策略（源代码仓库的 GitHub 推送已完成）。
- 对外 API、第三方系统集成、多用户权限体系。

### 3.3 结项结论

截至本次修订，Rust crate `0.2.5` 已发布，包含只读 `verify` 命令。当前实现的测试、CI、CodeQL 和安全报告状态见文末维护更新；正式结项仍待实际负责人/接收人完成验收和签字。

## 9. 当前结项更新（2026-11-04）

- `verify` 新增可选 `--check-remote`：用 `git ls-remote` 确认 Git-only 记录的提交是否仍被远端引用指向，给出 `remote-verified`/`remote-moved`/`remote-unreachable`/`remote-skipped` 四种状态；存在不可达远端时返回退出码 `1`，但仍输出完整报告。`restore` 新增可选 `--check-remote`：复用同一 `git ls-remote` 预检，在写入前发现任一 Git-only 远端不可达时整批不开始并返回 `1`。默认行为与 manifest schema v2 均不变。
