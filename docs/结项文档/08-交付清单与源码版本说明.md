## 2. 交付概述

### 2.1 交付对象

交付对象为 `proj_janitor` 0.1.0（`v0.1.0` 结项基线 + post-v0.1.0 变更），一个本地单用户命令行工具，提供：

- `scan`：项目发现、体积/修改时间统计、Git 状态读取；
- `backup`：GitHub URL-only 记录、`tar.gz` 归档、按项目 manifest v2、SHA-256；
- `restore`：按 manifest 恢复 Git 项目或归档项目，校验 SHA-256、安全解压、不覆盖已有目录；
- `clean`：白名单清理计划、dry-run、显式确认删除、安全保护；
- CLI 文本/JSON 输出、退出码、帮助与版本信息；
- Python/Rust 自动化测试；历史 98 项 Python 测试结果另见第 5 节与 06；
- 结项文档 00～09 和 `docs/blog/2026-10-22-summary.md`、`docs/blog/2026-10-23-summary.md`；
- Rust crate `0.2.5` 发布标签和功能源码提交；历史 `v0.1.0` 标签仅指 Python 基线。

## 8. 发布说明（Release Note）

### 8.1 版本定位

本节是 `v0.1.0` Python 包的历史 Release Note。该标签（`f5bb224`）不含后续功能和缺陷修复；原始位置恢复在 `2d059ae` 加入，缺陷修复在 `c4fa6d9`，备份目标统一在 `763c41f`。Rust 0.2.0–0.2.5 的已发布内容见 `docs/发布记录/`；当前交付身份见第 11 章。

### 8.2 新增能力

- `scan`：项目发现、体积/修改时间、Git 分支与工作区状态、文本/JSON 输出。
- `backup`：
  - 对干净、已推送、无 stash/submodule/LFS 等阻塞条件的 GitHub 项目，仅记录 URL、分支、上游和提交 SHA；
  - 允许 HTTPS GitHub URL 内嵌 PAT，但 manifest 和 CLI 输出会脱敏；
  - 所有本地 tag 必须已推送且与远程同名 tag 指向同一对象；
  - 其余项目生成 `tar.gz`，记录 SHA-256、源大小、归档大小和回退原因；
  - 每个项目使用稳定目录 `DEST/<项目名>/`，归档和 manifest 共用该目录；
  - manifest v2；`BACKUP_DEST` 默认目录、`--backup-dest`、`--dry-run`、`--include-artifacts`、`--always-archive`；Python API 使用 `backup_dest`。
  - `BACKUP_DEST` 可设默认根目录；CLI 和 Python API 使用 `backup_dest`，不会与恢复的 `dest` 混用。
- `restore`：
  - 从 schema v2 manifest 恢复 Git 或归档项目；
  - 省略 `--dest` 时恢复到 manifest 记录的原始 `source` 位置；`--dest` 仍可恢复到新目录；
  - 原始位置模式校验 `source` 为绝对路径、无 `..`/NUL、项目名一致、目标不存在且非符号链接；
  - 原始位置的实际恢复需要交互确认；非交互或 `--json` 场景必须显式给出 `--yes`；
  - Git 使用 `clone --no-checkout` + `checkout --detach`，结果为 detached HEAD；
  - 归档默认校验 SHA-256，安全解压，不覆盖已有目标；
  - `--project`、`--dry-run`、`--no-verify`、`--json`。
- `clean`：
  - 白名单规则：`python-cache`、`python-env`、`node`、`build`、`editor`；
  - 默认 dry-run；
  - `--rules` 筛选；
  - `--apply` + 交互确认或 `--yes`；
  - 项目根、`.git`、符号链接保护。
- CLI：`projjan` 与 `python3 -m proj_janitor` 双入口；main 提供五个子命令；退出码 0/1/2。
- 历史测试：98 项 Python `unittest` 全部通过（`763c41f`）；当前测试见第 11 章。

### 8.3 行为变更与注意事项

- 与“所有项目都归档”的初始实现相比，`backup` 默认会对满足条件的项目使用 URL-only，不再生成 `tar.gz`；需要强制归档时使用 `--always-archive`。
- manifest 使用 `schema_version: 2`；初始实现的 manifest 没有版本字段，二者不是同一格式。
- post-v0.1.0 起，URL-only 允许 HTTPS GitHub URL 内嵌 PAT，但持久化和输出会脱敏；归档仍包含 `.git/config`，可能保留凭据。
- post-v0.1.0 起，URL-only 不再因为存在本地 tag 就回退；只有未推送、与远程对象不一致或无法查询的 tag 才阻止。
- post-v0.1.0 起，备份目录从 `backup-<时间戳>/manifest.json` 改为 `DEST/<项目名>/manifest-<时间戳>.json`；旧目录不会自动迁移。
- post-v0.1.0 起新增 `restore`；恢复不覆盖已有目录，不自动回滚批量恢复，也不联网预检远程提交是否存在。
- 原始位置恢复是后续行为变更：不写 `--dest` 时恢复到 manifest 的 `source`，不再默认写到当前目录下的项目目录；依赖 manifest 可信且路径布局与备份时一致。非交互或 `--json` 场景必须加 `--yes`。
- 上述 DEF-001～DEF-004 已在 `c4fa6d9` 修复并增加回归测试。
