## 8. 发布说明（Release Note）

### 8.1 版本定位

`v0.1.0` 是 `proj_janitor` 的首个内部版本，定位为本地单用户 CLI，用于项目盘点、保守备份和安全清理。没有历史版本升级路径。

### 8.2 新增能力

- `scan`：项目发现、体积/修改时间、Git 分支与工作区状态、文本/JSON 输出。
- `backup`：
  - 对干净、已推送、无 stash/submodule/LFS 等阻塞条件的 GitHub 项目，仅记录 URL、分支、上游和提交 SHA；
  - 其余项目生成 `tar.gz`，记录 SHA-256、源大小、归档大小和回退原因；
  - manifest v2；
  - `--dry-run`、`--include-artifacts`、`--always-archive`。
- `clean`：
  - 白名单规则：`python-cache`、`python-env`、`node`、`build`、`editor`；
  - 默认 dry-run；
  - `--rules` 筛选；
  - `--apply` + 交互确认或 `--yes`；
  - 项目根、`.git`、符号链接保护。
- CLI：`projjan` 与 `python3 -m proj_janitor` 双入口；退出码 0/1/2。
- 测试：38 项 `unittest` 全部通过。

### 8.3 行为变更与注意事项

- 与“所有项目都归档”的初始实现相比，v0.1.0 的 `backup` 默认会对满足条件的项目使用 URL-only，不再生成 `tar.gz`；需要强制归档时使用 `--always-archive`。
- manifest 使用 `schema_version: 2`；初始实现的 manifest 没有版本字段，二者不是同一格式。
- `clean --json` 不是严格纯 JSON（DEF-001）；脚本消费前必须评估。
- `clean --list-rules` 需要占位 `ROOT`（DEF-004）；使用 `projjan clean . --list-rules`。
- `coverage` 规则可能匹配源码目录（DEF-002）；清理前必须人工审查。
- 批量备份的归档异常未隔离（DEF-003）；失败时可能没有 manifest。
