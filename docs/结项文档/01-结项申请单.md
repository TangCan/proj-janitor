## 2. 项目背景与目标

本地开发目录长期积累后，常出现项目分散、体积不清、依赖缓存和构建产物占用大量空间、旧项目源码是否已推送难以判断等问题。人工清理存在误删源码和 Git 历史的风险。

本项目目标：

1. 只读盘点本地项目，输出体积、时间和 Git 状态。
2. 对可恢复项目记录远程 URL 与提交 SHA，避免重复打包。
3. 对不可恢复项目生成可校验的 `tar.gz` 归档。
4. 按白名单清理构建产物，默认不删除，删除前必须显式确认。
5. 始终保护项目根目录、`.git` 目录和符号链接目标。

## 6. 遗留事项与风险

| 编号 | 事项 | 影响 | 处理建议 |
| --- | --- | --- | --- |
| L-01 | 仓库未配置 remote，`v0.1.0` 未推送 | 他人无法从远程获取源码 | 配置远程并推送 `main` 与标签 |
| L-02 | 无外部验收签字 | 结项材料缺少甲方确认 | 内部项目由负责人确认；如有甲方则补签 |
| L-03 | 无 `restore` 子命令 | 恢复需按 manifest 手工操作 | 后续版本评估实现 |
| L-04 | 单项目异常可中断整批备份 | 大批量备份可能提前结束 | 后续改为单项目隔离错误 |
| L-05 | 归档未内置 SHA-256 校验命令 | 完整性校验需手工执行 | 后续版本增加校验选项 |
| L-06 | 归档默认包含 `.git` | 归档体积偏大 | 后续评估排除策略并保证可恢复性 |

详细风险与变更见 `09-风险与变更记录.md`。
