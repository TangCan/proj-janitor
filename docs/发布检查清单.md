# proj-janitor 发布检查清单

适用 Python `0.1.x` / Rust `0.7.x` 双端发布。目标：任何一次上传前，都有本地验证与 CI 绿灯证据。

## 0. 前置条件

- [ ] main 最新提交的 CI 全绿（18/18 jobs），没有红灯 tag 待处理。
- [ ] 本轮变更已在 [09-风险与变更记录](结项文档/09-风险与变更记录.md) 记录 CR 编号，并在 [06-测试报告与缺陷清单](结项文档/06-测试报告与缺陷清单.md) 有测试证据。
- [ ] crates.io 未接近 24h 滚动限额（约 10 次/24h）。

```bash
python3 tests/cross_version_compat.py target/debug/projjan

```

## 4. PyPI

- [ ] Actions → `Publish Python package` → Run workflow：
  - `tag` = `python-v0.1.x`
  - `publish` = `true`
- [ ] `validate` 作业会检查该 commit 是否存在成功的 CI run；未绿会直接失败，不会构建或上传。
- [ ] 记录工作流 run ID。

## 5. crates.io

推荐用 Actions → `Publish Rust crate`：

- `tag` = `v0.7.x`
- `publish` = `true`
- 需要仓库 secret `CARGO_REGISTRY_TOKEN`；未配置时发布作业会明确失败
- `validate` 会校验 tag/Cargo.toml/Cargo.lock/发布记录，并要求该 commit 有成功 CI run
- 首次可先用 `publish = false` 演练：会执行 `cargo package` 与 `cargo publish --dry-run`，跳过上传

本地后备方案（仅在 tag CI 绿灯后）：

```bash
cargo publish --dry-run --locked
cargo publish --locked
```

- [ ] 记录工作流 run 或本地发布结果；注意 crates.io 24h 限额。

## 6. 发布后验证

```bash
python3 -m pip install --no-cache-dir --no-deps --target /tmp/pj-verify proj-janitor==0.1.x
PYTHONPATH=/tmp/pj-verify python3 -m proj_janitor --version

CARGO_HOME=/tmp/pj-cargo-home cargo install --locked --version 0.7.x proj-janitor --root /tmp/pj-rust-verify
/tmp/pj-rust-verify/bin/projjan --version
```

- [ ] 两端输出分别为 `projjan 0.1.x` / `projjan 0.7.x`。
- [ ] PyPI 与 crates.io 页面可访问，版本号为本次发布版本。

## 8. 失败处理

- **PyPI 已上传不可覆盖**：不要复用版本号；修复后发新补丁版。
- **crates.io 已上传**：可用 `cargo yank --version <ver>` 撤回解析，但仍应尽快发修复版。
- **门禁失败**：先在 main 修 CI 并重跑；绿灯后重新 dispatch 发布工作流。
- **Windows 偶发用例**：确认是否并发负载导致；单 job 重跑通过后可继续，但需在总结中记录。
