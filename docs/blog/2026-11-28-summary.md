### verify 当前能力

- 归档：SHA-256；加密归档在提供 passphrase 时解密并校验内部成员/路径
- Git bundle：SHA-256 + 魔数头；加密 bundle 支持 passphrase 解密校验
- 增量：逐级读取 base manifest，校验链上每个归档；加密基线同样解密校验
- 输出：人类可读后缀 + `--json` 的 `inner_checked`；无法内部校验时明确警告
- 恶意内容：`verify` 与 `restore` 共用成员校验规则，恶意路径在 verify 阶段即被拒绝

### 磁盘预检

- `backup --check-space`：archive 估算；git_bundle 告警跳过
- `restore --check-space`：inventory → `source_bytes` → 扫描；同一父目录合计；稀疏/超大成员提前停止；git 计划告警跳过

## 使用建议

- 推荐升级到 `0.1.114` / `0.7.114`。
- 恢复前空间预检：

  ```toml
  [restore]
  check_space = true
  ```

  或单次 `projjan restore --check-space ...`。
- 加密归档/增量链建议在恢复前运行：

  ```bash
  projjan verify <manifest> --decrypt-passphrase-file <passfile>
  ```

- 含 C0/C1、`Cf`（ZWJ/ZWNJ 除外）、Tag 字符或 `U+2028`/`U+2029` 的归档会被拒绝；普通 Unicode 文件名不受影响。
- 重要项目建议 `--always-archive`、保留完整增量链和 passphrase，并避免对不可信归档使用 `--no-verify`。
