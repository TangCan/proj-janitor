### `restore --check-space` 当前语义

估算顺序：

1. manifest `inventory` 的 `size` 汇总（含加密归档）；
2. 加密/增量归档回退 `source_bytes`；
3. 两者都缺失时才输出 warning 跳过。

普通未加密归档仍扫描归档头，避免把被排除产物算入。同一目标父目录下的多个归档按合计大小检查，扫描以剩余预算为上限；累计超过预算时立即停止，1TB 稀疏归档可在秒级拒绝。默认关闭，可用配置或 CLI 开启。

### 安全加固回顾

`0.1.94` / `0.1.95` 起归档路径拒绝：

- Unicode 双向控制字符（RLO/LRO/LRI/ALM 等，CR-216）；
- C1 控制字符 `U+007F`–`U+009F`（CR-217）；
- Unicode Tag 字符 `U+E0000`–`U+E007F`（CR-224）；
- 全部 `Cf` 不可见格式字符，仅保留 ZWNJ/ZWJ（CR-228）；
- 行/段分隔符 `U+2028`/`U+2029`（CR-229）。

普通 Unicode 文件名（中文、emoji、NBSP）不受影响。

## 使用建议

- 推荐升级到 `0.1.105` / `0.7.105`。
- 需要恢复前空间预检时：

  ```toml
  [restore]
  check_space = true
  ```

  或单次 `projjan restore --check-space ...`；`--no-check-space` 可覆盖配置。
- 含 C0/C1、`Cf`（ZWJ/ZWNJ 除外）、Tag 字符或 `U+2028`/`U+2029` 的归档会被拒绝；普通 Unicode 文件名不受影响。
- 重要项目仍建议 `--always-archive`、保留 passphrase，并避免对不可信归档使用 `--no-verify`。
