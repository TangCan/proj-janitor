## 当前能力概览

### 发布与供应链

- 双端版本/标签/发布记录一致性检查；
- CI 成功门禁（PyPI 与 Rust 发布共用）；
- PyPI Trusted Publisher、crates.io token；
- GitHub Release notes 从发布记录自动渲染。

### 恢复空间预检

- `restore --check-space`（默认关闭，可配置 `[restore].check_space`）；
- 估算顺序：manifest `inventory` → 加密/增量回退 `source_bytes` → 扫描；
- 同一目标父目录合计检查；稀疏/超大成员提前停止；
- git/git_bundle 计划告警跳过（CR-236）。

### 归档路径与解压安全

- 拒绝路径穿越、绝对路径、硬链接、设备/FIFO、Windows 保留名（含 Unicode/NFKC 变体）；
- 拒绝 C0/C1、双向控制、Tag 字符、`Cf`（仅保留 ZWJ/ZWNJ）、`U+2028`/`U+2029`；
- 符号链接必须留在项目内；恢复先暂存后发布，失败不留下半成品。

### 配置与可发现性

- `projjan init` 模板与 README 示例包含 `restore.check_space`；
- 三态 CLI：`--check-space` / `--no-check-space` / 配置默认；
- Unix 新建目录 `0700`、文件 `0600`（受支持范围）。

## 使用建议

- 推荐升级到 `0.1.106` / `0.7.106`。
- 需要恢复前空间预检时：

  ```toml
  [restore]
  check_space = true
  ```

  或单次 `projjan restore --check-space ...`；`--no-check-space` 可覆盖配置。
- 含 C0/C1、`Cf`（ZWJ/ZWNJ 除外）、Tag 字符或 `U+2028`/`U+2029` 的归档会被拒绝；普通 Unicode 文件名不受影响。
- 重要项目建议 `--always-archive`、保留 passphrase，并避免对不可信归档使用 `--no-verify`。
