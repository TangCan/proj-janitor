## 版本发布

- Rust `proj-janitor 0.2.6` 已发布至 crates.io，tag 为 [`v0.2.6`](https://github.com/TangCan/proj-janitor/releases/tag/v0.2.6)，GitHub Release 已创建。
- 功能代码提交：`c58c67c4fddd1b08f45fb383554b00ec32413e7c`；Python 包仍为 `0.1.0`。
- 版本包含 `--exclude-git-metadata`、干净 GitHub 项目的子模块轻量备份/恢复、默认 GitHub LFS endpoint 的轻量备份/恢复，以及近期归档和 manifest 身份检查改进。
- `cargo publish --locked` 上传成功；随后从 crates.io 安装 `0.2.6`，`projjan --version` 输出 `projjan 0.2.6`。
- 随后 Rust `proj-janitor 0.2.7` 也已发布，tag 为 [`v0.2.7`](https://github.com/TangCan/proj-janitor/releases/tag/v0.2.7)，crate 页面为 <https://crates.io/crates/proj-janitor/0.2.7>。它隐藏 Rust `backup --help` 中 `BACKUP_DEST` 的实际路径；Python 备份清理改进仍只在 main 源码中。
- Rust `proj-janitor 0.2.8` 已发布，tag 为 [`v0.2.8`](https://github.com/TangCan/proj-janitor/releases/tag/v0.2.8)。这是 README 修订版：crates.io 展示的安装说明不再把旧版本写成最新，并移除错误候选状态；发布后另发现 `SECURITY.md` 相对链接仍指向未打包文件，已在主分支修正。程序行为与 0.2.7 相同。
- Rust `proj-janitor 0.2.9` 已发布，tag 为 [`v0.2.9`](https://github.com/TangCan/proj-janitor/releases/tag/v0.2.9)。它将安全策略链接修正带入 crates.io 包内 README；程序行为与 0.2.8 相同。
- Rust `proj-janitor 0.3.0` 已发布，tag 为 [`v0.3.0`](https://github.com/TangCan/proj-janitor/releases/tag/v0.3.0)。该版本加入适用条件受限的 Git bundle 策略，并保留 GitHub Git-only 与归档两种现有策略。
- 随后修复 Python 备份失败清理边界：`os.fdopen` 失败或归档名被并发抢占时，仅清理身份匹配的本次输出；身份查询 `fstat` 失败会关闭描述符，POSIX 回归验证替换路径文件不会被删除。该实现已包含在后续主分支中。

## 仍需跟进

- 正式内部验收意见和签字仍需项目负责人/接收人填写；发布和 CI 通过不替代验收。
- Git-only 备份长期恢复依赖主仓库远端、固定子模块提交和 LFS 对象仍可访问。
- Windows Python 清理仍采用路径校验回退；是否需要抵御同一用户并发替换，应根据产品威胁模型决定。
