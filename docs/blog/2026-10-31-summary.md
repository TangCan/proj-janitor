# proj-janitor 项目最新进展与后续计划（2026-10-31）

## 1. 项目状态

`proj-janitor` 是本地项目盘点、备份、恢复与安全清理工具，提供 Python 与 Rust CLI，共用 schema v2 manifest。

- Python 包：`proj-janitor 0.1.0`，支持 Python `>=3.10`。
- Rust crate：`proj-janitor 0.2.5` 已发布到 crates.io；main 上的 `0.2.6` 仍是候选版本，尚未打 tag 或发布。
- 当前功能源码提交：`29fc7ce`；最近结项文档提交：`a28f1fa`；公开仓库：<https://github.com/TangCan/proj-janitor>。
- 功能代码与结项文档均已推送至 `origin/main`。

本文件以下内容记录此前维护快照；最新维护提交及其状态见文末“本次补充”。

## 2. 近期进展

### 2.1 保护归档中的 Git 凭据

本阶段连续补强了默认归档回退前的本地凭据检查，覆盖 remote fetch/push URL、多个 URL、子模块 URL、损坏或不可解析的 `.gitmodules`、Git 配置 include、HTTP `extraHeader`、credential password、URL rewrite、proxy/LFS endpoint、项目内 credential-store 文件和自定义 `core.sshCommand`。

最新一项修复处理 credential helper 的不透明参数：helper 使用未识别的参数时，可能把编码凭据放进 `.git/config`，而此前只检查常见明文标记。现在自动归档会拒绝未知 helper 参数；保留标准 `cache --timeout` 与 `store --file` 形式，并继续拒绝项目内 credential 文件。相关代码与回归测试见提交 `c0edbb4`。最新检查也拒绝 `store --file` 的 shell 引号/变量/命令替换/glob 路径，避免路径检查和 shell 实际访问位置不一致（`dd11274`）。

明确使用 `--always-archive` 或 `--include-artifacts` 仍会按调用者要求归档，可能把项目配置中的凭据一起保存；归档前仍需检查敏感内容。

### 2.2 备份与清理的边界保护

- 备份规划会拒绝 restore 无法跨平台接受的项目目录名，避免生成不可恢复的 Git-only manifest（`83b810d`）。
- 清理执行时保留计划生成时记录的规范项目根目录，并删除规范化后的目标；若项目根目录被替换为外部符号链接，会拒绝清理（`0b66ab4`）。
- 清理使用根目录和目标身份校验：Python POSIX 使用目录文件描述符，Rust 核对目录 capability 的根身份后执行相对删除；Windows Python 暂保留路径回退。目标在确认前被替换时拒绝删除；未在真实重要项目上执行清理。

### 2.3 Python 兼容性与安装验证

Python CI 现覆盖 3.10–3.15 的 Ubuntu，以及 3.12、3.15 的 macOS 15 和 Windows 2025。wheel 构建、临时安装和 `projjan --version` 冒烟验证在最低支持版 3.10 与最新测试版 3.15 的 Ubuntu job 中执行。增加跨平台 3.15 测试后，Python 安装/用例以及 Rust 跨平台矩阵均通过。

### 2.4 Git 轻量备份演练

干净且远端可恢复的 Git 子模块与默认 GitHub Git LFS endpoint 可使用 Git-only 备份，不生成压缩包。Cline 临时演练验证了主仓库、固定子模块提交和 LFS 对象恢复。Git-only manifest 不镜像子模块或 LFS 对象，长期恢复仍依赖这些远端对象存在。

## 4. 下一步计划

1. **继续评估 Python Windows 清理的并发边界。** 目标身份检查已覆盖确认前替换；Windows 仍用路径回退，检查与最终删除之间的竞态需明确或进一步收窄。
2. **稳定后再发布 Rust 0.2.6。** 在发布前复核候选源码、schema/归档互操作、`cargo package`、MSRV、三平台 CI、crates.io 安装以及发布记录；当前不把 main 候选称为已发布版本。
3. **继续维护凭据规则。** 记录当前 credential helper allowlist；新增 helper 支持时要求明确安全参数并增加 Python/Rust 回归用例。
4. **完成正式结项手续。** 实际负责人/接收人仍需审阅交付范围、接受遗留风险并填写验收意见和签字；自动化测试和公开发布不代替该确认。

技术交付、公开源码、MIT 许可、Rust 0.2.5 发布、Python/Rust 测试和跨平台 CI 均已建立。Rust 0.2.6 尚未发布；Python Windows 路径回退的清理竞态、强制归档绕过自动凭据保护、真实用户目录上的完整破坏性操作和正式验收签字仍是明确边界。
