# proj-janitor 项目进展（2026-11-04）

## 最新状态

- Rust `proj-janitor 0.4.0` 已于 2026-11-03 发布至 crates.io，tag [`v0.4.0`](https://github.com/TangCan/proj-janitor/releases/tag/v0.4.0) 指向 `c18fab1ebf7b29a198be3e64845dc374d12fcafc`，GitHub Release 已创建。该版本新增手动备份保留：`prune BACKUP_ROOT --keep N` 默认只预览，`--apply` 需终端确认、非交互或 JSON apply 需 `--yes`；只删除过期 manifest 及其未被保留清单引用、位于同一项目目录的 archive/bundle，孤立文件与旧时间戳运行目录不动。manifest schema 仍为 v2，Python/Rust 共用同一规划行为与 JSON 结构。
- 发布后 main 已完成 5 项跨实现一致性修复（CR-083–CR-087），当前 main 与已发布 crate 存在行为差：
  - `afe0485`：Python prune 复用 Windows 可移植组件校验，与 Rust 一致拒绝 `CON` 等不安全 manifest 项目名。
  - `fcb5fcd`：Python prune 只接受 JSON 整数 `schema_version: 2`，不再把 `2.0` 隐式当整数；两端新增单测与跨实现异常 manifest 矩阵（浮点/布尔 schema、保留项目名、超范围序号）。
  - `b7f5f14`：Python Windows 可移植路径校验拒绝 ASCII `DEL`（U+007F），与 Rust 对齐。
  - `daefebf`：Rust Windows 设备名规范化改用 Unicode 大写，与 Python 一致拒绝 `CONıN$` 等别名。
  - `1d40cac`：Python/Rust archive 路径校验拒绝非 UTF-8 组件，Rust 备份同时拒绝无法以 UTF-8 记录的源路径与符号链接目标；跨实现演练确认失败时不遗留 manifest/archive。该 fixture 需要任意字节文件名，macOS 文件系统不支持，因此限定在 Linux runner 执行。
- Python 首发进入“就绪待配置”状态：`docs/发布记录/0.1.0-Python版.md` 记录 tag `python-v0.1.0`（→ `5c033b762115ffe757c11280938bef8b916251f1`）已推送但不会自动上传；`publish-python.yml` 改为默认安全 dry-run，校验 tag 可达 main 且版本匹配后构建 sdist/wheel、`twine check`、隔离安装并上传 artifact，PyPI 上传 job 仅在 `publish=true` 且配好 Trusted Publisher 后执行。包页改用专用 `README-PyPI.md`，README 与用户手册补上 `pipx install git+https://github.com/TangCan/proj-janitor.git` 的源码安装入口。PyPI 上仍无本项目，源码元数据版本为 `0.1.0`。
- CI 新增 Python 发行包检查（`a351359`）：Ubuntu 3.15 job 构建 sdist + wheel 并 `twine check`、隔离安装后运行 `projjan --version`；3.10 job 保留 wheel 构建安装检查。
- 新增 `verify --check-remote` 远端可达性预检（CR-088，本轮工作区变更，尚未提交）：Git-only 记录用 `git ls-remote` 确认提交是否仍被远端引用指向，状态为 `remote-verified`/`remote-moved`/`remote-unreachable`/`remote-skipped`，`--json` 增加脱敏 `remote` 对象；存在不可达远端时仍输出完整报告并返回退出码 `1`。默认行为、`restore` 流程与 manifest schema v2 不变；含凭据的 URL 不联网也不传给 Git，探测单次 30 秒超时并禁用交互式凭据提示。Python 与 Rust 同步实现，文本与 JSON 报告逐字段一致。
