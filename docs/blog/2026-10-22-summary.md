## 3. 关键设计与安全约束

- 仅使用 Python 标准库，降低安装与运行成本。
- `requires-python = ">=3.10"`，当前验证环境为 Python 3.12.3。
- `clean` 默认 dry-run，只有显式传入 `--apply` 才执行删除。
- 非交互环境执行 `--apply` 必须提供 `--yes`，否则退出码为 2。
- 永不删除项目根目录和 `.git`。
- 只删除白名单构建产物；路径必须位于项目根目录内。
- 跳过 symlink，不跟随链接，也不进入已匹配目录继续扫描。
- `backup` 默认排除构建产物，避免把可重建内容写入归档。
- 退出码约定：成功为 0；根目录或部分处理失败为 1；拒绝删除或缺少确认参数为 2。
- 代码中不添加额外注释，保持骨架简洁。

## 5. 已知问题与限制

以下均不阻断当前骨架使用，但后续应处理：

- `backup --dry-run` 的显示名称尚未复用实际归档的重名消歧逻辑，同名项目时展示可能与真实文件名不一致。
- 单个项目在备份过程中发生 `OSError` 时会中止整个备份，可能留下没有 manifest 的半成品目录。
- `clean --apply --json` 会混入人类可读文本，不利于脚本稳定解析。
- 通用 `coverage` 规则存在误匹配 Python 源码目录的风险；dry-run 可降低风险，但执行前仍需人工确认。
- 多个重叠根目录可能导致清理计划重复计数。
- git 命令失败或超时会返回 `unknown`，这是保守行为，但缺少对超时与锁竞争的专门测试。
- 当前没有配置文件、定时任务、恢复命令、备份保留策略。
- `python3 -m venv` 在当前环境不可用，原因是 `ensurepip` 缺失，需要 `apt install python3.12-venv`；已通过 wheel + prefix 完成打包验证，不影响代码本身。
- 尚未提交 commit，也尚未推送到远程仓库。
