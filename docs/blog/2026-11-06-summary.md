- **本轮（CR-093）`backup --incremental` 增量备份（差异归档/变更检测）已完成实现并提交**（`a0b77a9`，2026-11-05 推送至 main；随后两个 CI 修复提交 `de6c218` 与 `2a91546` 亦已推送）。范围限定为 **archive（tar.gz）策略**；`git`（只记录远程信息）与 `git_bundle`（打包整个仓库历史）策略不受影响。变更检测采用内容哈希：对每个文件（及符号链接目标）计算 SHA-256，与上一快照的 `inventory`（完整文件清单 path→sha256/size）比对，变更/新增的文件写入差异归档，删除的路径（上一清单存在而当前不存在）记录到 `incremental.deleted`。
- **数据模型（schema_version 2，可选字段，向后兼容）**：`Record` 新增 `inventory`（每个快照的完整文件清单）与 `incremental`（`{base: <上一快照清单文件名>, deleted: [路径]}`，仅差异快照有）。完整快照不写 `incremental`；差异快照的 `base` 指向上一个快照清单文件名，可串成链。
- **恢复**：先沿 `incremental.base` 链回退到最近的完整快照，解出基线（创建目标目录），再逐级正向应用每个差异（先按 `deleted` 删除路径，再原位覆盖差异归档，处理文件↔目录类型切换）。
- **保留（方案 A：链整体保留）**：`--keep` 保留时，对每个保留的快照沿其 `incremental.base` 链保护所有祖先（不删除、归档保留），从而保证整条链完整；实际保留数可能略超 `keep`。
- **接口与配置**：`backup` 新增 `--incremental`（默认关）；`.proj-janitor.toml` 支持 `[backup].incremental = true`；优先级为 命令行 > 配置文件（命令行只能开启，配置也可开启）。排除规则（CR-092 的 `[backup].exclude`）已同时作用于 `inventory` 与差异归档，二者尊重排除。
- **CI 修复**：功能提交 `a0b77a9` 的首次 CI（`42032014911`）在 Windows Python 3.12/3.15 的 `test_batch_run_isolates_project_failures` 失败；`de6c218` 的修复（改为规范化路径比较）后 CI（`42033387811`）仍在 macOS 与 Windows 的同一用例失败。根因：`scan_project` 对项目路径做了 `resolve()`，而测试 mock 却与未解析的原始 `Path` 比较；macOS 上 `/var` → `/private/var` 符号链接、Windows 上 8.3 短名会使解析后的遍历根与原始路径不一致，导致 mock 从不命中、bad 项目未按预期失败。已修复为与 `bad.resolve()` 比较（`2a91546`），并在 Linux 上用符号链接根复现验证：旧比较不命中、新比较命中。
