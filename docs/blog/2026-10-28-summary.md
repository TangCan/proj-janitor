# proj_janitor 项目进展与 Rust 0.2.5 正式发布（2026-10-28）

## 1. 项目目标与当前阶段

`proj_janitor` 是本地项目盘点、备份、恢复与安全清理 CLI：

- CLI 命令：`projjan`
- Python 包：`proj_janitor`，版本 `0.1.0`
- Rust crate：`proj-janitor`，当前发布版本 `0.2.5`
- 子命令：`scan`、`backup`、`restore`、`verify`、`clean`
- manifest：Python 与 Rust 共用 schema v2

Rust `0.2.5` 已发布至 crates.io，并创建 Git 标签 `v0.2.5` 和 GitHub Release。项目仍处于持续维护阶段；正式结项结论、验收意见和签字仍待实际负责人/接收人完成。

## 2. 本阶段主要进展

1. 发布 Rust crate `0.2.5`，将只读 `verify` 纳入正式版本。
2. `verify` 对 archive 记录校验 manifest 中的 SHA-256；对 Git 记录只验证 URL 和 commit 元数据，不联网确认远程仓库或提交可用性。
3. 修复 Windows Rust CLI 子进程调用时的栈溢出：命令在 8 MiB 栈线程中运行。
4. Unix 依赖 `signal-hook` 更新至 `0.4.5`；CI 的 `actions/setup-python` 固定更新至 v7.1.0。
5. 更新 00–09 全套结项文档、README 和发布记录，使其反映 0.2.5、当前测试数量和最近 CI 证据。
6. 审查 Dependabot 更新：合并通过 CI 的 `signal-hook` 和 `setup-python` 更新；`sha2 0.11.1` 因摘要类型不再实现 `LowerHex` 而编译失败，关闭该 PR，保留 `sha2 0.10.9`。

## 5. 当前安全边界与未验证项

- `verify` 的 Git 结果是 `metadata-only`，不会检查远端可用性；archive 校验依赖 manifest 中的 SHA-256，不是来源签名。
- 性能、压力、容量、长期稳定性、系统化渗透测试尚未完成；重要用户项目的灾难恢复演练仍待执行（临时样例和公开仓库副本演练已通过）。
- 备份内容未加密；Unix 新建备份目录和文件分别使用 `0700`/`0600`，Windows 继承目标父目录 ACL。
- GitHub Release 提供源码和发布说明，没有附带预编译二进制；安装 Rust 版可运行 `cargo install --locked proj-janitor`。

## 7. 发布后的空间优化维护

对一个大型归档的分析发现，压缩包里主要空间来自 Git 历史和已压缩的项目归档文件。为保留默认备份的完整性，当前 main 增加了显式的 `--exclude-git-metadata`：archive 策略下可跳过 `.git`，manifest 在 archive 策略启用该选项时写入 `exclude_git_metadata: true`；该字段表示选项状态，不表示源项目一定含有 `.git`；恢复后是工作树快照，没有 Git 历史、分支、tag 或 remote。该选项未包含在已发布的 crates.io `0.2.5` 或 PyPI `0.1.0` 中，使用者需从 main 安装，且只应在不需要 Git 历史时启用。

新增验证：Python 131 项测试、Rust 26 项单元测试和 8 项 CLI 集成测试通过；Python/Rust 跨版本演练确认两种实现都能生成不含 `.git` 的归档，并互相 verify 与 restore。原始备份未被修改。
