## 更新内容

- CR-220：`restore --check-space` 的估算顺序改为：
  1. manifest `inventory` 的 `size` 汇总；
  2. 对加密/增量归档回退到 manifest `source_bytes`；
  3. 两者都没有时才告警跳过。
- 因此增量归档和无 `inventory` 的加密归档也能得到保守的空间预检，而不是只能跳过。
- 普通未加密归档仍优先扫描归档头，估算更贴近实际内容。
- 与 Rust 端行为一致。
