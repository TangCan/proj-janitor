## 更新内容

- Windows 归档恢复支持项目内文件和目录符号链接；越界链接仍会被拒绝。
- 在原始位置恢复确认前，CLI 现在列出每个项目的名称和目标原路径。
- `Cargo.toml` 声明 Rust MSRV 1.88；CI 增加 1.88 工具链测试。

## 验证

- `cargo publish --locked` 成功；从 crates.io 安装指定版本后，`projjan --version` 输出 `projjan 0.2.2`。
- 使用安装版在临时目录通过 PTY 演练原路径恢复：确认提示列出项目名和目标路径；回答 `n` 不写入，回答 `y` 后文件与符号链接恢复成功。
- Linux、macOS 15、Windows 2025 上的 Rust 格式、Clippy 和 12 项测试通过；MSRV 1.88 的测试通过。
- Python 3.10、3.11、3.12 上的测试通过。
- Windows CI 日志显示文件和目录符号链接往返测试实际执行成功。
- GitHub Actions 运行：<https://github.com/TangCan/proj-janitor/actions/runs/40086662781>。
- Python 与 Rust 双向 schema v2 归档恢复冒烟通过，包含 SHA-256 校验和项目内符号链接；该检查现已加入 CI。
- 使用 crates.io 安装的 `0.2.2` 对公开 GitHub 仓库执行 URL-only 备份和恢复演练；远程 tag 检查通过，恢复 HEAD 与 manifest commit 一致，恢复后的 Git 工作区干净。数据仅写入临时目录。

## 注意事项

- Windows 符号链接创建需要运行账户拥有相应系统权限。若无权限，恢复会失败并清理临时解压目录。
- 交互式原路径恢复会在确认前打印计划写入的具体目标路径；非交互调用仍须提供 `--yes`，`--json` 原路径恢复同样需要 `--yes`。
