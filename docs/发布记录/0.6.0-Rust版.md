## 更新内容

- `.proj-janitor.toml` 配置文件（CR-090）：为既有选项提供默认值——`[backup].dest`（默认备份目标，`--backup-dest` 与 `BACKUP_DEST` 均缺省时使用）与 `[prune].keep`（默认保留数量，`--keep` 缺省时使用）。优先级为命令行 > 环境变量 > 配置文件 > 报错；`--config <PATH>` 覆盖发现，否则从当前目录向上查找；严格校验（未知键拒绝、`keep` 须为正整数、`dest` 非空）。Rust 采用 `toml` crate，Python 采用 `tomllib`（3.11+，3.10 自动安装 `tomli`）。
- `backup --keep N`（CR-091）：成功备份后复用既有保留计划，对每个项目目录仅保留最近 N 份 manifest 及其引用归档；非交互（无 TTY）需 `--yes`，否则只打印计划不删除；交互以 `[y/N]` 确认；`--dry-run` 不生效。`[backup].keep` 提供默认值，`--keep`/`[backup].keep`/`[prune].keep` 均校验为正整数。
- `[backup].exclude`（CR-092）：配置 glob 排除模式，archive（tar.gz）策略归档时按项目根相对路径逐段匹配，跳过匹配的文件/目录（目录匹配则跳过整个子树）；`git`/`git_bundle` 策略不受影响；空模式与花括号展开 `{a,b}` 被拒绝；Rust 采用 `globset`，Python 采用 `fnmatch`，语义一致。
- `backup --incremental`（CR-093）：archive 策略差异快照。对每个文件（及符号链接目标）计算 SHA-256，与上一快照的 `inventory`（完整文件清单 `path→sha256/size`）比对，变更/新增文件写入差异归档，删除路径记录到 `incremental.deleted`；`incremental.base` 指向上一个快照清单文件名串成链。恢复 = 先解最近完整快照，再逐级应用差异（先删后叠）。保留采用方案 A 链整体保留（`--keep` 不会删除链上的祖先）。`--incremental` 命令行开关 + `[backup].incremental` 配置默认值；`git`/`git_bundle` 策略不受影响；排除规则对 inventory 与差异均生效。
- manifest schema v2 不变（`inventory` 与 `incremental` 为可选字段，向后兼容）；Rust 与 Python 行为保持对齐。
