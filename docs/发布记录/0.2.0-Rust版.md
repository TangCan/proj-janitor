## 发布验证

- `cargo package --locked` 打包并验证成功。
- `cargo publish --dry-run --allow-dirty --locked` 预检成功。
- `cargo publish --locked` 发布成功。
- 从 crates.io 执行 `cargo install proj-janitor --version 0.2.0 --root <临时目录>` 成功；安装程序报告 `projjan 0.2.0`。
- Rust 版 9 项单元与 CLI 集成测试通过；Clippy 全目标检查通过。
- Python 版 98 项测试此前在 Python 3.12.3 上通过；Python 包版本仍为 `0.1.0`。
- 发布后新增归档越界、清理边界和远程 tag 对比测试；当前 Rust 测试为 12 项，本地全量通过。首次 GitHub Actions CI 对发布版的 9 项 Rust 测试及 Python 3.10/3.11/3.12 测试全部通过。
- 随后提交 `24d0ec5` 将 Rust CI 扩展到 Linux、macOS 和 Windows，并修正 Windows 路径格式测试；GitHub Actions 运行 <https://github.com/TangCan/proj-janitor/actions/runs/40084347291> 中，12 项 Rust 测试在三平台全部通过，Python 3.10/3.11/3.12 测试也全部通过。
- 0.2.0 初始版的 Windows 符号链接恢复尚未实现；后续补入 Rust 源码，并在 `0.2.1` 中发布。见 `docs/发布记录/0.2.1-Rust版.md`。

## 范围与限制

- Rust 与 Python 共用 `projjan` 可执行命令名，但作为独立分发版本维护。
- manifest schema v2 保持兼容。Rust 版默认进行 URL-only GitHub 备份判定，不符合条件时回退归档。
- GitHub URL-only 判定使用本地仓库证据；标签远程查询及真实 GitHub 远程恢复尚未在 CI 中验证。
- 归档恢复拒绝越界路径和特殊文件；项目内符号链接恢复仅在 Unix 上支持。
- CI 工作流在本次发布后增补，首轮执行结果以 GitHub Actions 页面为准。
